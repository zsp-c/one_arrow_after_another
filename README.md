# 一箭又一箭（Python + Pygame）

一个参考微信小游戏《一箭又一箭》核心玩法实现的小游戏作业。棋盘上摆着若干带方向的箭头，
点掉挡路的，放走能走的，直到棋盘清空。

本项目为独立实现，未使用原游戏的任何素材、代码或关卡数据。

---

## 一、运行方法

```bash
pip install pygame      # 唯一的第三方依赖，本机已安装 pygame 2.6.1
python main.py
```

开发用的两个附加命令（都不弹窗口，用来验证）：

```bash
python check_levels.py         # 关卡自检：搜出每关的通关顺序并逐步回放校验
python main.py --auto          # 自动试玩：按求解结果把 4 关全部打通一遍
python main.py --shots         # 把各个界面渲染成图片存到 _shots/
python main.py --scale 1.5     # 强制指定界面缩放倍率（默认按屏幕自动挑）
```

环境：Python 3.12 + pygame 2.6.1（Windows 11 实测通过）。没有 pygame 时中文字体会自动
回退到系统字体，找不到中文字体也不会崩溃。

## 一之二、清晰度 / 分辨率说明

界面按 1000×700 的“设计基准尺寸”编写，**启动时按显示器可用空间自动挑一个缩放倍率**
统一放大（例如 1920×1080 @125% 缩放的屏幕 → 倍率 1.35 → 窗口 1350×945）。
所有尺寸、圆角、线宽、字号都乘以这个倍率，所以放大后是真正按物理像素重绘的，不是把
小图拉大。

这里有个容易踩的坑，也是最初画面发虚的原因：

> Windows 在 125% / 150% 显示缩放下，如果进程**不是 DPI 感知**的，系统会先把窗口按
> 逻辑像素渲染、再**位图拉伸**到物理像素贴到屏幕上。于是 1000×700 的界面被插值放大成
> 1250×875，所有文字和箭头边缘都会发虚——问题不在渲染分辨率，而在于“被系统拉伸”这一步。

所以 `main.py` 在 `pygame.init()` **之前**调用 `SetProcessDpiAwareness(2)` 声明
per-monitor DPI 感知（非 Windows 平台会自动跳过），再用 `SPI_GETWORKAREA` 读取
**物理像素**的屏幕可用区域来挑选倍率。声明之后窗口不再被系统拉伸，每个像素 1:1 映射，
文字与箭头边缘就是锐利的。

倍率会取到 0.05 的整数倍，并保证窗口（含标题栏）放得进屏幕；范围限制在 0.8x ~ 2.0x。
如果自动挑的倍率不合意，用 `--scale` 手动指定即可。

## 二、玩法规则

棋盘是若干行列的网格，每个格子里最多有一支箭头，方向为上、下、左、右四种。

点击一支箭头后，程序沿它所指的方向朝棋盘边界逐格检查：

- **前方没有其他箭头** → 箭头飞出棋盘并被消除；
- **前方有别的箭头** → 箭头不能消除，会朝前顶一下再被弹回来、闪红、并冒出“被挡住了！”
  的提示，同时把挡路的那支箭头用金色方框标出来；这次点击**消耗一次失误机会**。

清空本关全部箭头即通关并进入下一关；失误次数耗尽则本关失败，可以重新开始。

> 判定口径与作业要求一致：**只看同一行或同一列、箭头与边界之间还有没有其他箭头**，
> 不涉及其他机关。

界面上的辅助提示：鼠标悬停在某支箭头上时，会把它前方的路径画出来——
路径上的小圆点**绿色**表示畅通、**金色**表示可以走到这里、**红色**表示被这支箭头挡住
（红色方框就是挡路者），被挡住之后的格子会变灰（无关紧要）。前方畅通时，棋盘对应的
那条边上还会出现一条绿色出口。

## 三、操作说明

| 操作 | 说明 |
| --- | --- |
| 鼠标左键点击箭头 | 尝试让这支箭头飞出棋盘 |
| 鼠标移动 | 悬停查看该箭头的前进路径 |
| `R` | 重新开始本关（恢复到初始状态） |
| `Esc` | 返回主菜单 |
| `Enter` / `空格` | 开始游戏、进入下一关、重开本关 |

游戏界面左侧是棋盘，右侧信息栏依次显示：剩余箭头数、本关箭头总数与已飞出数、
剩余失误（红点表示还剩几次）、已失误次数、本关提示、清空进度条，以及**重新开始本关**
和**返回主菜单**两个按钮。顶部显示当前关卡序号与关卡名称。
界面共三个：开始界面、游戏界面、通关 / 失败结算界面。

## 四、关卡与通关顺序

共 4 关，全部由程序搜出顺序并逐步回放验证过（见 `check_levels.py`）。
坐标写法为 `r行c列`，行列都从 0 开始，与 `check_levels.py` 的输出一致。

### 第 1 关 · 初识箭头（5×5，5 支箭头，失误上限 3 次）

```
      c0  c1  c2  c3  c4
  r0   ·   ·   ·   ·   ^
  r1   ·   <   ·   ·   ·
  r2   ·   ·   ·   ·   ·
  r3   ·   >   ·   v   ·
  r4   ·   ·   ·   v   ·
```

通关顺序：`r0c4`(上) → `r1c1`(左) → `r4c3`(下) → `r3c3`(下) → `r3c1`(右)

设计意图：先用两支本来就能飞出的箭头熟悉规则，再引出“r3c3 挡住 r3c1、r4c3 挡住 r3c3”
的两级连锁。本关失误给得宽松，允许试错。

### 第 2 关 · 连锁反应（6×6，8 支箭头，失误上限 3 次）

```
      c0  c1  c2  c3  c4  c5
  r0   ·   ·   ·   ·   ·   v
  r1   ·   >   ·   ·   v   ·
  r2   ·   ·   ·   ·   ·   ·
  r3   ^   ·   ·   ·   ·   ·
  r4   ^   ·   <   ·   <   ·
  r5   ·   ·   ·   ^   ·   ·
```

通关顺序：`r0c5`(下) → `r3c0`(上) → `r4c0`(上) → `r4c2`(左) → `r4c4`(左) →
`r1c4`(下) → `r1c1`(右) → `r5c3`(上)

设计意图：左下角一条“上→上→左→左→下→右”的六连链，必须从链条末端倒着拆。

### 第 3 关 · 十字路口（6×6，11 支箭头，失误上限 3 次）

```
      c0  c1  c2  c3  c4  c5
  r0   ·   ·   <   ·   ·   ·
  r1   ·   ·   ^   ·   ·   <
  r2   ·   ·   ·   v   ·   ^
  r3   ·   ·   ·   ·   ·   ^
  r4   ^   ·   ·   <   ·   ·
  r5   <   ·   ·   >   ·   ^
```

通关顺序：`r0c2`(左) → `r1c2`(上) → `r1c5`(左) → `r2c5`(上) → `r3c5`(上) →
`r4c0`(上) → `r4c3`(左) → `r5c0`(左) → `r5c5`(上) → `r5c3`(右) → `r2c3`(下)

设计意图：最右列叠了四层（r1c5 → r2c5 → r3c5 → r5c5），中间还夹着一条独立的
“r4c0 → r4c3 → r2c3”链，两条链互不干扰但容易看混。

### 第 4 关 · 环环相扣（7×7，12 支箭头，失误上限 2 次）

```
      c0  c1  c2  c3  c4  c5  c6
  r0   ·   v   ·   ·   v   ·   <
  r1   ·   ·   ·   >   ·   v   ·
  r2   ·   ·   ·   ·   ·   ·   ·
  r3   ·   <   ·   ·   ·   ·   ·
  r4   ·   ·   v   ·   ·   ·   <
  r5   ·   ·   ·   ·   ·   <   ·
  r6   <   ·   <   ·   ·   ·   ^
```

通关顺序：`r0c4`(下) → `r3c1`(左) → `r0c1`(下) → `r0c6`(左) → `r5c5`(左) →
`r1c5`(下) → `r1c3`(右) → `r6c0`(左) → `r6c2`(左) → `r4c2`(下) → `r4c6`(左) → `r6c6`(上)

设计意图：本关箭头最多、失误最少。右下角 `r6c6` 被 `r4c6` 和 `r0c6` 两支箭头同时卡住，
必须先把两条互不相干的链都清干净它才走得掉，是全场最后一步。

## 五、文件说明

| 文件 | 作用 |
| --- | --- |
| `main.py` | 图形界面：DPI 感知与自适应缩放、绘制、动画、输入、界面状态机（开始 / 游戏 / 通关 / 失败） |
| `game_logic.py` | 纯逻辑：方向、路径判定、关卡状态、求解器。**不导入 pygame**，可独立运行 |
| `levels.py` | 4 个关卡的字符画数据，改关卡只需要改这里 |
| `check_levels.py` | 关卡自检脚本：搜通关顺序、回放校验、碰撞 / 重开 / 判负校验 |
| `_shots/` | `python main.py --shots` 生成的界面截图 |

把逻辑和渲染分开，是为了让“路径判定是否正确”“关卡是否可解”这类问题能脱离图形界面
自动验证——`check_levels.py` 和 `main.py --auto` 都只依赖 `game_logic.py`。

### 动画与视觉反馈

- **飞出**：箭头沿方向加速飞离棋盘，带三层残影拖尾、逐渐淡出，并在原位置溅出火花；
- **碰撞**：箭头朝前顶出去再弹回来（`sin` 曲线），同时由本色渐变到红色、描白边，
  冒出“被挡住了！”的飘字，挡路的箭头被金色方框脉冲闪烁两下；
- 动画播放期间会锁住鼠标输入，避免连点导致状态错乱。

### 怎么改关卡

编辑 `levels.py`，用字符画描述棋盘即可（`^ v < >` 是箭头，`.` 是空格），
改完跑一遍 `python check_levels.py` 就能确认新关卡有没有解、以及推荐怎么点。

## 六、验证情况

`python check_levels.py` 对每一关做四件事，全部通过：

1. 用求解器搜出一条**零失误**的通关顺序（深搜 + 局面去重剪枝）；
2. 把这条顺序通过真正的规则入口 `LevelState.click()` 逐步点一遍，确认每一步都合法、
   最后棋盘清空；
3. 点一支被挡住的箭头，确认箭头**不会消失**、失误次数减一、并返回挡路者坐标；
4. 调用 `reset()` 后确认箭头数量、失误次数、失误计数全部复原；
   连续失误到上限后 `is_failed` 为真。

```
全部 4 关检查通过：均存在零失误通关顺序，且无死局。
```

`python main.py --auto` 则进一步驱动**真实界面代码**（`Game.click_cell`）自动通关：

```
  第 1 关 初识箭头   点击  5 次全部飞出，失误 0 次，界面状态 = win  通过
  第 2 关 连锁反应   点击  8 次全部飞出，失误 0 次，界面状态 = win  通过
  第 3 关 十字路口   点击 11 次全部飞出，失误 0 次，界面状态 = win  通过
  第 4 关 环环相扣   点击 12 次全部飞出，失误 0 次，界面状态 = win  通过
  失误耗尽 -> 失败界面：通过
  重新开始恢复初始状态：通过
```

调试期间这套验证发现过一个真实问题：第 3 关最初把 `r3c5`(下) 和 `r5c5`(上) 摆成了互相
阻挡，形成死局（无论怎么点都清不空）。求解器报出无解后改成了现在的布局。

> 说明：本作业只要求单格箭头的点箭头玩法，未加入额外机关或复杂玩法。
